# 簽章私鑰保管

讀者：負責建置、簽署與復原 AI Usage Dashboard 的維護者。

正式 feed 私鑰的工作副本使用 Windows DPAPI CurrentUser 保護，放在 source repository 之外，檔案權限只允許保管者。這份工作副本依賴 Windows 使用者環境；恢復途徑是另外保存的加密備份與口令。

## Google Drive 備份

備份使用獨立口令加密的 PKCS#8 檔案，存於維護者個人 Google Drive 的專用、未共用資料夾。只上傳加密備份，不上傳明文私鑰、DPAPI 工作副本或口令。加密口令須與 Drive 備份分開保管，且在原電腦無法使用時仍能取得。

上傳前確認目的資料夾只允許保管者存取；上傳後再核對檔案及父資料夾的一般存取權均為「受限制」。受限制仍可能包含已獲授權的人員，須一併檢查存取清單。[Google Drive 共用設定](https://support.google.com/drive/answer/2494822?hl=zh-Hant)

Google Drive 是雲端異地備份，不能記為離線媒體。持續登入的帳號遭接管、檔案被刪除或帳號無法恢復，都可能影響備份的可用性；單純存在同步資料夾不代表已成功上傳。保管者須另保留可用的 Google 帳號復原途徑。

## 建鑰與還原驗證

1. 在本機互動輸入口令及確認值，不經聊天、CLI 參數、環境變數或一般日誌傳遞。保管工具使用新檔建立，遇到既存材料時停止，避免覆寫既有私鑰。
2. 產生正式私鑰、受保護的工作副本與加密備份，讀回實際備份 bytes，確認完整解析、公鑰 fingerprint 及簽章驗證。
3. 上傳加密備份後，從 Google Drive 重新下載到另一個受控本機位置；不得以原始本機檔案或同步快取冒充下載結果。
4. 以原始保管紀錄及公鑰核對下載檔的大小與 SHA256，在新的 process 以口令還原，再執行產品 `FeedSigning sign` → `verify` 整合。短暫明文 PEM 只能存在於已限制權限的自有暫存目錄，完成或失敗時都須清除並回驗。
5. 記錄實際 Drive 資料夾 URL、保管者確認的存取狀態、上傳與重新下載狀態、備份雜湊、公鑰 fingerprint、還原結果及工具來源。紀錄不包含口令、私鑰內容或加密檔內容。

只有上述實際往返與還原通過，才算完成正式備份驗收。工具演練或本機複製只證明其測到的範圍；同機還原不能記成跨機恢復實測。`offlineMediaConfirmed` 保持 `false`。

本機保留的加密備份及下載副本仍須限制存取；清理前先確認遠端備份和口令均可用。私鑰遺失、洩漏及換鍵流程見 [feed 格式](UPDATE_FEED_FORMAT.md)；正式候選與公開條件見 [發布流程](../RELEASING.md)。
