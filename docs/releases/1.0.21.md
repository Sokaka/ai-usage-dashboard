# AI Usage Dashboard 1.0.21

`1.0.21 / sequence 1035` 為候選版本；source SHA、Windows CI、候選 workflow 與六件凍結成品紀錄待本次驗證完成後填入。目前正式版本與下載資訊見 [README](../../README.md#current-release)。Updater 預計沿用前一正式版 `v1.0.20` 交付的 `1.0.18` 原始 bytes，須通過候選沿用檢查。

## 本版內容

- 修正 Claude Code 官方簽章有效，但來源與舊副本上層目錄有額外修改權限時，Dashboard 仍拒絕執行的情況。來源 ACL 安全時維持直接執行官方原始 EXE；只有來源 ACL 不符合直接執行規則時，才建立受保護副本。
- Claude 副本改放在 Windows system-volume root 下的目前使用者專用目錄，避開 profile 內原有的額外寫入權限。新位置與全部上層仍須通過路徑及 ACL 檢查，並保留檔案鎖定、SHA-256、官方簽章與帳號隔離。
- Claude Code 最低版本仍為 `2.1.169`；其他 provider 的 CLI 版本要求維持不變。

## 升級

直接更新 Dashboard 即可使用本次修正，無須為此重裝 Claude 或手動修改原始 CLI 的權限。帳號、偏好、用量與 provider 綁定檔案格式維持原有契約；既有卡片不會只因 App 更新而要求重新連接。

新版在需要副本時使用 `%SystemDrive%\AiUsageDashboard.ClaudeCli.<current-user-SID>\executables-v1`。舊 `%USERPROFILE%\AiUsageDashboard.ClaudeCli\executables-v1` 不再作為預設副本位置；程式不會自動刪除舊副本，也不修改該目錄、來源 CLI 或其上層的 ACL。若新位置也無法建立或通過安全檢查，操作仍會停止，不能藉由升級繞過來源與權限驗證。

## 建置與驗證

本次合成 ACL 回歸針對來源與舊 profile 副本上層同時有額外修改權限的情況，以及新副本根目錄與祖先的拒絕條件。Release 建置、完整測試、production line coverage、同 source Windows CI、候選凍結與正式端點驗證的結果尚待回填，不引用其他工作樹或歷史版本的通過數字。

## 驗證範圍

問題診斷觀察到 Claude Code `2.1.296` 的官方簽章及副本內容有效，但這不是本版成品的登入或用量驗收。回報問題的成員電腦、Claude 真人登入、額度顯示、背景更新及舊版 CLI 的真人查詢仍待驗。

乾淨 Windows 安裝、既有標準安裝的一鍵線上更新、安裝後 UI／無障礙，以及其他四個 provider 的真人登入／用量，亦未以本版成品完成。合成回歸、建置與下載驗證不代替實機驗收。逐平台狀態見 [1.0.21 CLI 實測表](../CLI_COMPATIBILITY.md#1021)。
