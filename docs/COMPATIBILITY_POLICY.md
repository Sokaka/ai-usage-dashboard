# 升級與相容性原則

本文件是後續開發與發布必須遵循的要求：**新版 App 優先沿用舊資料、設定與仍安全相容的 CLI，讓使用者盡量直接更新後繼續使用。**
這不是所有歷史或未來版本均已相容的保證；目前實作見[技術總覽](TECHNICAL_OVERVIEW.md)，CLI 支援條件與實測結果見 [CLI 相容性](CLI_COMPATIBILITY.md)。

## 預設要求

| 範圍 | 開發要求 |
| --- | --- |
| 本機資料 | 保留已支援舊格式的讀取能力；新增欄位使用明確預設或遷移，不因 App 更新清空帳號、排序、主題或視窗設定。 |
| 持久化契約 | 帳號 ID、資料路徑、檔名、Credential Manager target 與既有欄位語意維持穩定；必要變動須明確遷移。 |
| 登入與連接 | 同一 Windows 使用者、同一電腦升級時，保留仍有效且可驗證的綁定；不只因 App 版本變更要求全部重新登入。匯入、換機、登入失效或身分無法驗證仍依既有安全流程重新連接。 |
| CLI | 優先維持已支援舊版與官方新版的共同功能；先評估能力檢查或有限的版本適配，不只為配合最新 CLI 就提高最低版本。Copilot 以本機官方 CLI 搭配 App 固定的 SDK，兩者版本分開記錄並驗證；主包不再隨附第三方 CLI。 |
| 更新與復原 | 驗證既有安裝直接升級及中斷後復原；程式版本切換與資料格式相容性須一起考量。不能假設換回舊 EXE 就能讀取新資料。 |

## 資料格式變更

- 修改前列出涉及的格式與已支援版本。需要新格式時明確標示版本，保留舊 reader 或可重複執行的遷移；不可沿用同版號偷偷改變欄位語意。
- 寫入前完整驗證來源，透過既有 transaction／journal 等機制保存必要的復原狀態；失敗或中斷不留下半套設定，也不刪除原本可用的帳號資料。
- 遷移與復原沿用私人資料的 ACL 與憑證保管方式；備份不能讓 token／私鑰進入匯出檔或公開紀錄。
- 遇到無法辨識的新格式或損壞資料時，保留原檔並提供可處理的錯誤，不以空白預設覆寫。若只有部分操作安全，須明確界定可讀與禁止寫入的範圍。
- 不把未知欄位一律忽略當成相容策略；涉及帳號、安全、用量或 signed feed 的資料，仍須符合各自契約。feed 格式變更依 [UPDATE_FEED_FORMAT.md](UPDATE_FEED_FORMAT.md)。

## 必要的不相容變更

只有在官方撤除能力、必要功能無法安全適配、安全問題或其他可驗證限制下，才縮減已承諾的相容範圍；不能僅以減少維護工作為由移除支援。

變更必須附上：

- **原因與範圍**：哪些 App、資料格式或 CLI 版本受影響，以及無法保留相容性的證據。
- **處理方式**：優先自動遷移；需要使用者操作時，在 Release 說明列出最少必要步驟，不把刪除設定或全部重新登入當作預設解法。
- **失敗復原**：保留可復原資料，交代安全重試、修正版本或既有離線復原路徑；不放寬線上反降級、來源或簽章檢查。
- **停止支援安排**：可預先通知時，先公布替代方案與停止支援版本；安全問題須立即停止時，說明原因與修復方式。

## 變更與發布驗證

依改動範圍驗證下表，保留 App／格式／CLI 版本及結果；不適用項目須說明原因。發布時同時遵循 [RELEASING.md](../RELEASING.md)。

| 情境 | 必須確認 |
| --- | --- |
| 舊格式 → 新 App | 涵蓋仍承諾支援的各格式版本；載入、必要遷移、儲存與重啟後，資料及欄位語意仍正確。 |
| 既有安裝 → 新 App | 至少涵蓋前一發布版，以及仍在支援範圍的較舊版本跨版更新；保留卡片、偏好與有效綁定。Copilot 由隨附 CLI 改為本機官方 CLI 時，另驗證缺少 CLI 的安裝提示，以及安裝完成後沿用有效綁定；不預先清除憑證。 |
| 舊 CLI／官方新版 → 新 App | 涵蓋受影響平台仍支援的舊介面、排錯基準與最新正式版；執行方式及真實登入／用量紀錄依 [CLI 相容性維護](../INTERNAL_DISTRIBUTION.md#cli-相容性維護)。 |
| 遷移中斷與復原再中斷 | 原資料可保留或復原，重試不重複套用、不覆寫其他帳號，也不留下半完成的登入清理。 |
| 新格式 → 舊 App／復原版本 | 確認可讀範圍與寫入保護；若舊 App 無法安全處理，須有可驗證的資料復原方案或明確限制，不能宣稱可直接降版。 |

一般回歸測試使用去識別 fixtures，不連真實帳號。CLI 無法安全取得或尚未實測時明列待驗；未完成的必要項目不能寫成升級相容性已通過。
